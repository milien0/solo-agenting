# Build and deliver

Read the task's buyer need, experiment evidence, expected artifact, allowed write scope, permissions, and acceptance condition. Avoid silently replacing the buyer problem with a more interesting technical project. Identify the smallest complete result that can satisfy the need or test the hypothesis.

Implement in the assigned scope. Use configured integrations and official current documentation when behavior is uncertain. Keep secrets and customer data out of public artifacts and source. Respect licenses and intellectual property. Record dependencies, hosting commitments, and likely recurring costs.

Verify the complete path needed by the task: artifact opens, promised function works, delivery link is accessible to the intended recipient, and payment/delivery terms match the actual product. Tests should prove meaningful behavior, not mirror implementation. Report validation gaps candidly.

Return artifact paths or live URLs, version/reference, evidence of checks, known limitations, remaining obligations, and next action. Deployment or publication requires real account readiness and authorization. A built local artifact is not a published service, and a published service is not a sale.
