# Improve the harness

Use a trace, repeated failure, verified customer need, or measured bottleneck to define the improvement. Keep the goal tied to better execution, lower cost, stronger evidence, or reliable recovery. Do not change the challenge's metric, window, revenue verification, or funding records to improve apparent performance.

Inspect the installed framework docs before changing APIs or discovery paths. Review new plugin/skill source and the resulting diff. Capability installation is separate from account authorization. Never modify credential controls, audit records, permission checks, or secret handling to evade a denied action.

Make a small versioned change and verify the actual failed behavior or needed flow. Preserve prior durable data and provide recovery steps for state migrations. Run discovery and build/type checks appropriate to the change. Record what changed, evidence, measured effect, and limitations; do not claim an improvement solely because code was written.
