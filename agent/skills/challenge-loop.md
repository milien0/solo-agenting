# Challenge cycle

Inspect challenge status, elapsed time, verified funding, gross revenue, refunds, costs, task queue, account readiness, outstanding deliveries, and the last meaningful outcome using discovered tools. If no live account is configured, continue preparation that produces a concrete artifact or resolves uncertainty.

Choose the next action based on expected learning or delivery value, time to result, executable capabilities, actual funds, and evidence from prior experiments. The strategy is open: do not assume a preset niche or continue an approach merely because it was the first one considered. Prefer completing an existing customer obligation over starting another speculative task.

Apply the standing inference-expense policy: inspect known usage and remaining monetary budget, choose the least expensive adequate available model and reasoning effort, and justify paid escalation. Account for tool charges, retries, and delegated workers. If no useful independent work is ready, persist the dependency and next wake condition/check with backoff and yield. Do not spend model calls repeatedly checking unchanged state or claim routing/budget enforcement that the runtime does not implement.

Give the action a falsifiable completion condition. For an experiment, name the unknown, test, observation, spend commitment, and continue/stop condition. For delivery, name the recipient requirement, artifact, acceptance evidence, and obligation remaining. For infrastructure, name the observed failure and health check that will prove recovery.

Run independent tasks in parallel with separate scopes, and keep dependent external actions sequential. Record authoritative evidence and useful artifacts through the durable store. Reconcile money using finance tools; a claim you wrote is not verification.

Close the cycle with: what was completed, evidence references, what was learned, verified gross revenue and unresolved adjustments, costs or commitments, exact blockers, and the next queued action. Do not claim that another worker will run unless the job was actually scheduled or queued.
